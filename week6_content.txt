Week Overview 
A stateless agent forgets everything the moment a conversation ends. Week 6 fixes 
that. Interns build the full memory stack   episodic memory of past events, semantic 
memory of facts and preferences, procedural memory of learned behaviours, and 
structured knowledge graphs that let agents reason about relationships between 
entities, not just keyword matches. 
By Friday, every intern's agent will remember users across sessions, learn from 
corrections, and traverse a structured knowledge graph to answer questions that 
retrieval alone cannot handle.

Hands-on Labs 
Three labs, increasing in complexity. Lab 6.3 is the most technically demanding lab in 
the programme so far   start it on Thursday. 
  
Lab 6.1   Memory-Augmented Chatbot 
Build a CLI chatbot backed by two memory stores: a SQLite episodic log (raw 
interaction history with timestamps) and a ChromaDB semantic index (embedded 
summaries of past sessions). On every new session, the agent queries both stores 
and injects the 5 most relevant past memories into context before responding. 
Demonstrate that the agent correctly references something said in a previous 
session without it being in the current context window. 
Validation  Test by running 3 separate sessions. In session 3, ask about something 
only mentioned in session 1. The agent must answer correctly using retrieved 
memory. 
  
Lab 6.2   Knowledge Graph Query Agent 
Build a knowledge extraction and query pipeline. Feed 20 text paragraphs (Wikipedia 
articles on a domain of your choice) to an LLM that extracts entities (people, 
companies, places, concepts) and relationships (works_at, founded_by, located_in, 
part_of). Store the graph in NetworkX. Build a query agent that converts natural 
language questions into graph traversals and answers multi-hop questions   
questions that require crossing at least two edges to answer. Visualise the final graph 
with pyvis (HTML output). 
Validation  Test with 5 multi-hop questions. At least 4 must be answered correctly by 
traversing the graph. A pure keyword search of the original text must fail on at least 2 
of the same questions. 
  
Lab 6.3   GraphRAG: Vector + Graph Hybrid Retrieval 
Build a GraphRAG pipeline: given a question, run vector retrieval (ChromaDB top-5) 
and graph traversal (NetworkX neighbourhood expansion) in parallel. Merge the 
contexts, deduplicate, and pass to an LLM for generation. Evaluate on 15 questions 
split into three categories: factual (vector wins), relational (graph wins), complex 
(hybrid wins). Report results in a structured comparison table. Implement automatic

Project 6-I-C: Procedural Memory & Self-Improving Agent 
Procedural Memory & Self-Improving Agent 
Difficulty 
Intermediate 
Overview 
Build an agent that learns from its own mistakes. When a user 
corrects an answer, the agent extracts the correction as a procedural 
memory (a rule), stores it, and ensures the same mistake never 
happens again. Over 20 interactions, the agent's error rate 
measurably decreases. The system tracks its own performance and 
plots a learning curve. 
Problem Solved 
Current AI systems make the same mistakes repeatedly because they 
have no procedural memory. An agent that extracts rules from 
corrections and applies them prospectively is a fundamentally 
different class of system   and the architecture to build it is non-trivial. 
System 
Architecture 
User Input → Response Generator (Groq) → User Feedback Handler → 
[if correction: Correction Extractor Agent → Rule Store (SQLite)] → Rule 
Retriever (retrieves relevant rules at generation time) → 
Rule-Augmented Prompt Builder → Improved Response Generator → 
Performance Tracker (SQLite) → Learning Curve Visualiser (matplotlib) 
→ Streamlit Dashboard 
Memory Design 
Procedural Store (SQLite): correction rules with fields: 
original_mistake, correction, rule_text, domain, confidence, 
application_count, last_applied. Rules retrieved by semantic similarity 
to current query (embedded with sentence-transformers). 
Application log tracks every time a rule fires. Rule consolidation: after 
5 identical corrections, merge into a single high-confidence rule. 
Technical Skills 
Procedural memory design, LLM-driven rule extraction, rule retrieval 
by semantic similarity, dynamic prompt construction, performance 
tracking, matplotlib learning curves, Streamlit dashboard

Problem Solved 
Standard RAG retrieves chunks. GraphRAG retrieves reasoning chains.

incrementally   new documents add nodes and edges without 
rebuilding. Entity resolution: LLM-based canonical name matching 
prevents duplicate nodes for the same entity.

Memory Design 
Four fully integrated memory types: Episodic (SQLite, per-user 
interaction log with importance scoring and recency decay), 
Semantic (ChromaDB per-user collection + structured user profile in 
SQLite JSON), Procedural (SQLite rule store with domain classification 
and confidence scores), Knowledge Graph (NetworkX per-domain 
graph, shared across users but queryable per-user context). 
Knowledge Gap Queue (SQLite priority queue of unresolved 
questions). Active Learning Log (SQLite, tracks what the agent 
researched autonomously and what it learned).
